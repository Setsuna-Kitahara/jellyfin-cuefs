# 09 · ARM64（树莓派 / 群晖 ARM / Apple Silicon / 各种盒子）

## 结论先说

| | `cuefs:latest`（完整版） | `cuefs:slim`（精简版） |
|---|---|---|
| amd64 | ✅ | ✅ |
| arm64 | ❌ | ✅ |
| TAK | ✅ | ❌（arm64 上没有可用路径） |

**ARM64 能跑，但只有精简版；精简版不支持 TAK。**

## 为什么不支持

TAK 的解码库是 **Windows x86-64 PE（DLL）**。要让 Linux 加载它，只有：

1. **Wine**：官方只提供 x86/x86-64 的 Wine 能跑这个 DLL。
   ARM64 上的 Wine 需要 x86-64 用户态模拟（qemu-user / box86 / FEX 之类），
   实测这类组合下 `wine64 + Windows Python + ctypes 加载 x86-64 DLL` 跑不起来（缺 32 位组件、PE 加载器不认）。
2. **反编译/重写解码器**：没有许可依据，工程量也不是个人项目能干的事（见 [02-TAK-LICENSE.md](02-TAK-LICENSE.md)）。

所以 ARM64 上我们不假装能支持 TAK，而是明确：**用精简版，处理非 TAK 的整盘格式**。

## ARM64 上你能做什么

精简版覆盖的整盘格式（ffmpeg 能解的都行）：

| 格式 | 扩展名 | 说明 |
|---|---|---|
| FLAC | `.flac` | 最常见，无损 |
| WavPack | `.wv` | 无损/混合 |
| TTA | `.tta` | 无损 |
| ALAC | `.m4a` / `.alac` | Apple 无损 |
| AIFF / WAV | `.aiff` / `.wav` | 未压缩 |
| APE / Monkey's Audio | `.ape` | 无损（ffmpeg 能解） |
| Musepack / Shorten | `.mpc` / `.shn` | 较老格式 |

用法与 amd64 完全一样，只是把镜像换成 `cuefs:slim`：

```bash
docker run -d --name cuefs --restart unless-stopped \
  -p 127.0.0.1:8099:8099 \
  -v /mnt/music-src:/music-src:ro \
  -v /mnt/music-overlay:/music-overlay \
  -v cuefs-cache:/cache \
  -e CUEFS_WORKERS=2 \
  cuefs:slim
```

## 如果你在 arm64 上确实有 TAK

三条现实的路：

1. **在 amd64 机器上转一遍**（推荐）：用完整版镜像 `--export` 成真实 FLAC，
   再把 FLAC 目录丢给 arm64 的 Jellyfin。多占一份空间，但从此与 TAK 无关。
   ```bash
   docker run --rm -v /mnt/tak:/music-src:ro -v /mnt/out:/export cuefs:latest --export /export
   ```
2. **amdx86 模拟**：`qemu-user-static` + `--platform linux/amd64` 跑完整版。
   能跑，但每次解码都过一层模拟，速度大约 1/3–1/5，而且 Wine 在模拟层上偶尔崩。
   小库可以忍，大库别试。
   ```bash
   docker run --platform linux/amd64 ... cuefs:latest
   ```
3. **双机**：TAK 留在 amd64 的机器上跑完整版，arm64 的 Jellyfin 通过网络挂过去
   （cuefs 是 WebDAV，天然可以跨机用 —— 记得开认证，见 [10-SECURITY.md](10-SECURITY.md)）。

## 构建 ARM64 镜像

`Dockerfile.slim` 支持 `TARGETARCH`，可以交叉构建：

```bash
docker buildx build -f docker/Dockerfile.slim \
  --platform linux/amd64,linux/arm64 \
  -t cuefs:1.5.0-slim -t cuefs:slim .
```

（`Makefile` 里有 `make multiarch`。）

完整版**没有** arm64 变体：`Dockerfile` 里 `FROM debian:trixie-slim` 默认平台，
且依赖 x86-64 的 Wine 与 DLL，交叉构建出来也跑不了。
